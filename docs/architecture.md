# Architecture

## Tech stack (decided)

- **Engine:** Godot 4.7.2 (pinned in `scripts/setup-godot.sh`, installed by the SessionStart hook to `~/.local/bin/godot`). Compatibility renderer (OpenGL 3.3): right for 2D pixel art, runs on old PCs and the Steam Deck, and on CPU-only cloud containers.
- **Language:** statically typed GDScript. Hot loops can move to a GDExtension later if profiling demands it.
- **Multiplayer:** host-authoritative. ENet over LAN now; later Steam relay via GodotSteam's MultiplayerPeer (same high-level code) and/or a headless dedicated server export.
- **Steam:** GodotSteam (later).
- **Rendering:** the world renders into a 640x360 `SubViewport` (`main.tscn`: `Stage/World/WorldView`), integer-scaled by whole pixels. The HUD, workshop, game over and menus live on the root canvas (stretch mode `canvas_items`, laid out in the same 640x360 units) so their text is drawn at full window resolution; `WorldView` reparents its UI layer to its scene owner for this. Large entity counts are drawn with `MultiMeshInstance2D`, never one node per bullet or enemy.

## Project layout (`game/`)

| Path | Layer | Rule |
|---|---|---|
| `sim/` | Simulation | Pure GDScript (`RefCounted`). No `Node`, scene tree, `Input`, `OS`, `Time`, or global `randf()`/`randi()`. Deterministic: all randomness comes from `world.rng`. Fixed tick 30 Hz. |
| `net/` | Networking | Host runs the sim. Clients send commands and receive snapshots. |
| `render/` | Presentation | Reads sim state every frame and never mutates it. |
| `tools/` | Dev tools | Screenshot scenarios. |
| `tests/` | Tests | Headless runner, no external addons. |
| `assets/` | Art | PNGs exported by `tools/artgen` (`python tools/artgen/generate.py --export-game-assets`). |

## Sim contract (`sim/`)

`SimWorld` (`sim/sim_world.gd`, `class_name SimWorld extends RefCounted`)
- Constants: `TICK_RATE := 30`, `DT := 1.0 / 30.0`, `ARENA := Rect2(0, 0, 2560, 1440)` (4 x 4 screens of the 640x360 viewport; playtest round 3: the old 1280x720 arena felt cramped). `SPAWN_ELLIPSE := Vector2(720, 400)`: radii of the 8 start / respawn slots around the arena centre (`NetSession.spawn_position()`, `_find_spawn_spot()`). **Alien spawn area:** `spawn_area()` = bounding box of the alive vehicles grown by `SPAWN_REACH := Vector2(640, 360)`, clipped to the arena (the whole arena when none is alive); aliens spawn on its edges (`SPAWN_INSET` inside), so they always arrive from off-screen at the same distance however big the arena is. The ground texture (`assets/ground_dune_sea.png`, `tools/artgen/export_assets.py: ground()`) has the arena size; `ARENA_W/H` there must match.
- State read by render/net:
  - `tick: int`, `seed: int`, `rng: RandomNumberGenerator`
  - `vehicles: Array[SimVehicle]`
  - Enemies as dense struct-of-arrays (length == `enemy_count`, swap-remove on death): `enemy_id: PackedInt32Array` (stable ids), `enemy_kind: PackedByteArray` (`SimWorld.MITE = 0`, `BOULDER = 1`, `SPITTER = 2`, `GLASS = 3`, `BROOD = 4`, `SHRIEKER = 5` (see "Species and the hive signature"), bosses `BOSS_A = 6` Tripod Queen, `BOSS_B = 7` Shard Colossus, `BOSS_SHARD = 8` a Colossus shard: see "Bosses (as built)"), `enemy_pos`, `enemy_vel: PackedVector2Array`, `enemy_hp: PackedFloat32Array`.
  - Projectiles as dense struct-of-arrays (length == `proj_count`): `proj_pos`, `proj_vel: PackedVector2Array`, `proj_ttl`, `proj_damage: PackedFloat32Array`, `proj_owner: PackedInt32Array` (vehicle id, `-1` = alien).
  - `events: Array[Dictionary]`: this tick's events, cleared at the start of `step()`. `{"type": "fire"|"hit"|"kill"|"vehicle_destroyed"|"spit", "pos": Vector2, "owner": int, "kind": int}` (more types are listed under the round loop and under "Stats and events for the UI"). `kill` and `vehicle_destroyed` carry extra keys when a rig is involved (see there).
- Methods:
  - `_init(p_seed: int)`
  - `add_vehicle(peer_id: int, pos: Vector2, p_name := "DRIVER", p_color := -1) -> SimVehicle` (name sanitised; colour < 0 keeps the default `id % 8`)
  - `get_vehicle_for_peer(peer_id: int) -> SimVehicle` (or `null`)
  - `apply_command(peer_id: int, cmd: Dictionary)`. Commands: `{"type": "set_drive", "value": "circle"|"kite"|"charge"}`, `{"type": "set_target", "value": "nearest"|"strongest"|"weakest"|"players_first"|"boulders"|"spitters"}`, `{"type": "set_rules", "scope": "rig"|<weapon kind>, "value": <rule text>}`, `{"type": "set_weapon_target", "scope": <weapon kind>, "value": <weapon target mode>}` (see "Doctrine rules").
  - `step()`: advances one tick (spawning, enemy AI, vehicle AI, weapons, projectiles, collisions via a spatial hash, deaths, scrap, events).
  - `checksum() -> int`: hash of the full state, for determinism and desync tests.

`SimVehicle` (`sim/sim_vehicle.gd`, `class_name SimVehicle extends RefCounted`)
- `id: int`, `peer_id: int`, `player_name: String` (default `"DRIVER"`; 1..16 printable ASCII chars), `color_index: int` (0..7 paint colour, default `id % 8`; 0 = red, 1 = magenta as in the current art, 2..7 reserved for more paints). `SimVehicle.sanitize_name(raw)` is the one place names are cleaned (printable ASCII only, spaces collapsed and trimmed, max `MAX_NAME_LEN = 16`, empty becomes `"DRIVER"`); `COLOR_COUNT = 8`.
- `pos: Vector2`, `vel: Vector2`, `heading: float` (radians, Godot convention: 0 = +X/east; sprites face north, so render rotation = `heading + PI / 2`), `hp`, `max_hp: float`, `alive: bool`, `scrap: int`, `kills: int`.
- `doctrine: Dictionary = {"drive": "circle", "target": "nearest"}` (the base settings), `rules: Array` (the rig's IF-THEN rules) and `weapon_doctrine: Dictionary` (weapon kind -> `{"target": String, "rules": Array}`); see "Doctrine rules".
- `weapons: Array[Dictionary]`, each `{"kind": "mg", "damage": float, "range": float, "cooldown_ticks": float, "cooldown": float, "aim": float, "heat", "jam", "sw", "shots": int}`. Fire rate is a fractional accumulator (a shot adds `cooldown_ticks`, the overshoot below one tick carries over; at most one shot per tick). `aim` is the world angle, updated by the sim so render can rotate turrets.

Sim details (clarifications, no contract change): `enemy_vel`/`proj_vel` are px/s; `proj_ttl` is seconds; event `kind` is the enemy kind hit/killed (`-1` for a vehicle), `fire` kind is `0` (mg), and for `vehicle_destroyed` `owner` is the destroyed vehicle's id. Extras on `SimWorld`: `spawning_enabled`, `spawn_enemy(kind, pos)`, `spawn_projectile(...)`, `query_enemies(...)`, `rebuild_derived()` (call after a snapshot rewrites the arrays: resets `enemy_count`/`proj_count` and the spatial hash). `checksum()` covers contract state only (not rng state or AI scratch).

Skeleton gameplay: vehicles drive themselves according to their doctrine; weapons auto-fire at targets in range. Mites chase the nearest vehicle and deal contact damage; boulders are slow and tanky. Spawn rate grows over time. Projectiles hit enemies and, from round `PVP_START_ROUND` on, other players' vehicles (PvP), never their owner. Kills give scrap.

## Net contract (`net/`)

- `NetSession` (`net/net_session.gd`, `class_name NetSession extends Node`): `host(port := 24680, auto_start := true) -> Error`, `join(address: String, port := 24680) -> Error`, `start_solo(name := "DRIVER", color_index := 0)`, `is_host() -> bool`, `local_peer_id() -> int`, `send_command(cmd: Dictionary)`, `var world: SimWorld` (never null after host/join/start_solo; in the lobby it is an empty placeholder that is not stepped). Signals: `peer_joined(id)`, `peer_left(id)`, `session_started`, plus the lobby signals below.
  - The host steps the sim in `_physics_process` (30 Hz) **only while a match runs**, applies client commands with the sender's peer id, and sends a snapshot every 2 ticks (unreliable-ordered).
  - Clients apply snapshots to their local `world` (only while in a match). Render smooths positions.
- **Lobby and match lifecycle** (host-authoritative). `state` is `NetSession.State.IDLE | LOBBY | MATCH` (`in_lobby()`, `in_match()`, `state_name()` = `"lobby"|"match"`).
  - `host(port, auto_start)` opens a lobby with the local player (profile from `set_profile()`, default `"DRIVER"`/0) and does not step the sim. `auto_start = true` (legacy `--host`, the default for now) calls `start_match()` immediately and accepts late joiners (`allow_late_join = true`). **The menu passes `auto_start = false`**, lets people gather, then calls `start_match()`. `join()` puts a client in the LOBBY state until the host's roster arrives; on connect it sends its profile as the hello.
  - `lobby_players: Array[Dictionary]`, host first, `{"peer_id", "name", "color_index", "ready", "is_host"}`; read-only for callers. Authoritative on the host, re-sent (reliable) to clients on every change and validated by `NetSession.parse_lobby()` on receipt. During a match it is the roster of connected players (a departed peer is removed). `local_player() -> Dictionary` is the local entry (`{}` until the roster arrived), `lobby_all_ready()` is true when every non-host player is ready.
  - Signals: `lobby_changed`, `match_started` (also on a rematch; `world` is then a fresh `SimWorld`, so re-bind render), `match_ended(winner_peer: int)` (game over reached, once per match, host and clients; -1 = nobody/solo loss), `join_rejected(reason: String)` (client only, followed by `disconnected`).
  - `set_profile(name, color_index)`: before host/join/start_solo it only stores the profile; afterwards it sends the validated command `{"type": "profile", "name": String (raw <= 64 chars), "color_index": 0..7}` (the same command is the client's hello). The host sanitises the name (`SimVehicle.sanitize_name`), makes it unique among players (case-insensitive: `"BOB"`, `"BOB 2"`, ... within 16 chars) and keeps colours unique: a new player gets the preferred colour if free else the lowest free one; a player who asks for a taken colour keeps the current one. Profile changes are accepted in the lobby and also during a match (the vehicle is updated).
  - `set_lobby_ready(bool)` sends `{"type": "lobby_ready", "value": bool}`; only meaningful in the lobby.
  - `start_match() -> Error` (host/solo only, state LOBBY, at least 1 player; ready flags are not required, so the host may force): builds a fresh world (seed `world_seed + n` for the n-th match of the session, random if `world_seed < 0`; `fast_rounds` applied), one vehicle per roster entry in roster order with its name and colour, then emits `match_started` (clients get a reliable `match_started` RPC and start from a fresh passive world). Errors: `ERR_UNAUTHORIZED` (not host), `ERR_UNAVAILABLE` (not in lobby), `ERR_UNCONFIGURED` (empty roster).
  - `rematch() -> Error` (host/solo only, only when `world.phase == PHASE_GAME_OVER`, else `ERR_UNAVAILABLE`): **chosen behaviour: straight into a new match**, not back to the lobby: new seed, same connected players with their names and colours, ready flags reset, `match_started` again. Solo restart uses the same call (`start_solo()` also still works and restarts at once).
  - **Late join:** a peer that connects while a match runs is **refused** (simplest robust option; no spectator mode): the host sends `join_rejected("match in progress")` and closes the connection after the message is flushed. Exception: sessions started with `auto_start = true` (`allow_late_join`) still take late joiners as players, as before. A full lobby (8 players) is refused with `"lobby full"`.
  - `leave()` (same as `stop()`): closes the connection and forgets the lobby; `world` is kept for inspection. Extras: `fast_rounds` (applied to every match world; `--fast` still works by setting `world.fast_rounds` after `host()`/`start_solo()`), `allow_late_join`, `player_count()` (roster size).
  - **Security:** every client message (game and lobby) goes through `validate_command` (allow-list, types, ranges, lengths) and the 20/s per-peer limit; `profile` and `lobby_ready` additionally share a stricter limit of 4/s per peer. Clients never send start/rematch (host-only API, no command exists for them). Host-to-client messages (`lobby`, `match_started`, `rejected`) are accepted only from peer 1 and the lobby list is validated (max 8 entries, unique peers and colours, exactly one host, sanitised names).
- `Snapshot` (`net/snapshot.gd`, format version 15; **version 7** added the doctrine rules, see "Doctrine rules"): `static func encode(world: SimWorld) -> PackedByteArray`, `static func apply(world: SimWorld, bytes: PackedByteArray)`. Positions quantized, events included. Vehicles carry `player_name` and `color_index` (right after `peer_id`; a colour index >= 8 makes `apply()` return false, names are re-sanitised on receipt). Projectile ttl is sent in 1/100 s (acid lives about 1.8 s). Event type `spit` was appended to `EVENT_TYPES`. Version 4 added `leader_peer` (s32, header) and `protect_ticks` (u8). **Version 5** (balance iteration 3) added `pvp_grace_ticks` (u16) and `fuel_drain` (u8) to the header (now 37 B), `invuln_ticks` (u8, after `protect_ticks`), a header flag `FLAG_STATS` (set outside combat) after which every vehicle carries its `round_stats` and `match_stats` (about 60 B each; absent during combat, where `apply()` keeps the receiver's last copy), an event type byte whose top bit (`EVENT_EXTRA_BIT`) appends 2 signed bytes (`kill`: `victim`, `weapon`; `vehicle_destroyed`: `cause`, `killer`) and the new event types `pvp_on`, `bounty`, `drain`. `contact_reduction` and `thorns` are derived from cards on receipt. **Version 6** quantizes positions to 1/16 px (`POS_SCALE = 16`, u16 covers 4096 px) for the 2560x1440 arena.
- `LanDiscovery` (`net/lan_discovery.gd`): the host broadcasts a UDP beacon on port 24681 once per second; clients emit `host_found(address: String, info: Dictionary)`. Beacon fields: `game`, `version` (1), `port`, `players`, `name`, `state` (`"lobby"` or `"match"`; unknown values parse as `"lobby"`). Set `lan.session = <NetSession>` and every beacon refreshes `players` (roster size), `name` (host's player name) and `state` from it; the plain fields `player_count`, `host_name`, `match_state` still work without a session.

Net details (as built):
- `NetSession` names itself `"NetSession"` and must sit at the same node path on every peer, because RPCs match by path.
- Extras: `player_count()`, `stop()`, signals `connection_failed` and `disconnected`.
- Client commands are validated against an allow-list and rate-limited to 20 per second per peer.
- `Snapshot.encode(world, events_override := [])` carries the events accumulated since the last snapshot. `Snapshot.apply()` returns `false` and leaves the world untouched on malformed data.
- Size: about 8 bytes per enemy, 13 per projectile, 7 per event and about 110 per vehicle (about 8.4 kB at 1,000 enemies, sent every 2 ticks).
- `world.events` holds only the latest tick's events, so render must consume them once per sim tick, not once per frame.
- `LanDiscovery` also emits `host_lost`.

Render details (as built):
- Every sprite that turns is pre-rendered by `tools/artgen/export_assets.py` as a strip of frames: 32 directions for hulls and 16 for aliens, using RotSprite with the outline drawn after rotating. Turrets, tracers and acid are drawn fresh at each angle.
- Godot only picks a frame and never rotates pixels on the GPU, which would make pixels jagged and shimmer at 640x360. Trade-off: the baked top-left lighting turns with the sprite.
- Effects consume `world.events` once per sim tick. Goo, scorch marks and tyre ruts persist in a decal layer.
- **Layered rigs** (`tools/artgen/rig.py`, `render/rig_art.gd`, `render/rig_view.gd`): a rig is a stack of sprites, one per baked strip: running gear (wheels, off-road tyres or tracks), hull, then one layer per armour, engine and behaviour card (`rig_plates/reinforced/ablative/spikes/v8/nitro/kit.png`) and per tech bolt-on (`rig_tech.png`: dozer blade, roll cage, sidecar, jerrycans, scrap pile; rows = footprint x `RigArt.TECH_KIT`, keyed by `tech_fx`). Every hull-fixed layer is drawn facing north on the same 72x80 canvas centred on the sim position and RotSprite'd into 80x80 frames, so frame k of every layer lines up; rows pick the variant (footprint x card level). The chassis (`SimVehicle.chassis`, engineering 1..4) picks footprint and body row (`rig_body.png` rows: buggy, buggy with welded frame, pickup, truck, war rig tractor): 1 = footprint A buggy (frame row with `engineering_frame`), 2 = footprint P four-wheel pickup with a painted bed, 3 = footprint B six-wheel truck with a closed cab, 4 = the war rig tractor on B plus an articulated trailer (render-only swing) that carries guns 3 and 4. Some tech maps onto card layers (`_tech_level`: spike skirts -> spikes 2, blast resist -> plates 2, armour shed -> ablative 2; welder / crane -> kit rows). Guns are mounted by `RigView._mount_plan` (hull 0, 1, then trailer, then hull 2, 3; with a sidecar the last gun sits on it); guns (`gun_<kind>.png`, rows = level) and nitro flames turn on their own and sit on anchors in `RigArt` (mirrored from `rig.RIG_ANCHORS`; `RigView.barrel(i)` gives tip, root and angle, `exhausts()` the pipe ends). `RigView` rebuilds its stack only when `RigArt.signature(v)` changes (cards, levels, weapons, chassis, tech, paint); per frame it only picks frames.
- **Paint keys:** paint-dependent pixels are baked as key colours `(255, 0, 8 + 16 * step)` and `render/paint.gdshader` swaps them for the owner's ramp from `paint_ramps.png` (row = `color_index`), so one strip serves all eight paints. The flat `buggy_<paint>.png` strips (menu preview) are composites of the starter layers.
- **UI text** (`render/ui_font.gd`, `UiFont`, replacing the old 3x5 / stencil bitmap fonts after playtest feedback that the font was hard to read): body text in Barlow Semi Condensed SemiBold at 8 units (`draw`, cap height about 6), fine print at 7 (`draw_small`, card effects and info boxes), headings and counters in Barlow Condensed ExtraBold at 10 units per `scale` (`draw_big`), and the Black Ops One stencil face for the title logo (`draw_title`, set on the blank `ui_logo_plate.png`). All OFL (`assets/fonts/OFL-*.txt`), all upper case, tabular figures. `pos` is the top-left of the capitals, so layouts keep working in rows (body pitch 9 to 10 units). Rusty plates and steel housings get a dark wash inside the frame (`UiKit.PANEL_WASH` / `STEEL_WASH`) so text sits on an even field; key hints sit on a dark strip (`UiKit.footer`). Rival name tags and hp bars over rigs are drawn by the HUD in screen space (`Hud._draw_rival_tags`, `WorldView.rig_radius`).
- **Moments and readability:** `vehicle_destroyed` spawns a big explosion, flying debris, wreck decals and a short camera shake (whole-pixel camera offset, never in screenshot mode). The HUD shows a full-width "PVP ON" banner when `world.pvp_enabled()` turns true (`WorldView.pvp_on_tick`, also recovered from the recorded history in screenshot mode), a bounty skull over `leader_peer`'s rig, a warm shimmer while `protect_ticks` or `invuln_ticks` > 0, hp numbers and a pulsing red edge vignette below 30% hp. The local rig stands on a dashed ground ring in its paint. Corpse decals are drained of colour and half transparent; boulders get a second soft dark rim and a longer, darker shadow; acid globs are 6 px with a trail.
- **Information UI (playtest round 1 #2, #5, #10, #11):** `WorldView` keeps a match log built from events once per sim tick (and by `prime()` in screenshot mode, so host, clients and screenshots agree): `kill_log` (player kills: killer, victim, weapon), `wreck_log` (`vehicle_destroyed`: cause, killer) and `drain_log`. The HUD shows a kill feed of player kills only (top right under the hive plate, 7 s, max 4 lines, rams in fire colour, lines with your rig hazard-edged), off-screen rival arrows at the screen edge (paint colour, a tag with hp and fuel gauges, smaller with distance, kept clear of HUD plates, bounty skull for the leader), the PvP grace countdown while `pvp_grace_ticks > 0`, a "camp drains N fuel" tape in the last 12 s of drain rounds, and "WRECKED BY ..." on the respawn / ELIMINATED panels. The workshop has a LAST ROUND recap under the header (`render/recap.gd`: death time and cause, killer and weapon from the kill log, damage taken by source as one stacked bar, kills / scrap / interest earned, fuel lost / stolen / drained) with a doctrine hint on the amber CRT when one source has >= 45% of the damage (boulders -> KITE, acid -> CHARGE, mites -> CIRCLE / NEAREST, a rival -> PLAYERS 1ST or KITE); its chips (or `H`) send `set_drive` / `set_target`. The status plate shows interest as `interest_for(v)` / `interest_cap_for(v)`, an UNDERDOG tape when `is_underdog(v)`, and flashes the drain amount. Hovering a convoy row shows that rival's dossier (fuel, hp, armour, speed, guns and parts with levels, tech per branch, doctrine) in the tech column; a click pins it. Round stats are only shown when `round_stats.round == world.round` (clients keep stale copies during combat).
- **Spectator mode:** when the local rig is eliminated and others play on, `WorldView.spectating()` turns true 3 s after the last wreck (the HUD shows ELIMINATED meanwhile); the camera follows `spectated()`: the rig picked with Tab / Right (next), Shift+Tab / Left (previous), else the auto choice (one side of the closest rival pair within 300 px, preferring the leader, else the leader, else the best score; re-evaluated every 3 s); Home or A returns to auto. The HUD then shows SPECTATING with the name, the watched rig's status and doctrine, and live standings; the workshop shows a read-only panel (your match so far, your recap, standings where a click watches a rig, the watched rig's dossier) instead of the shop. Keys are handled in `render/hud.gd`.
- **Minimap** (`render/minimap.gd`, a Control on the HUD layer owned by `WorldView.minimap`, combat only): the whole arena scaled to fit `Minimap.MAX_INNER` (112x64) at the arena's aspect, so it follows any arena size, in a rusty plate in the bottom-right corner; the off-screen rival arrows treat `Minimap.frame_rect()` as a HUD panel. It shows the ground texture darkened (a plain field if the texture does not span the arena), the camera's view box (from the canvas transform), alien density as cyan pixels (one pixel per map cell, brighter where more crowd; boulders and spitters the brightest specks; rebuilt into a small ImageTexture every frame), rigs as paint-coloured dots (the followed rig, local or spectated, as a heading arrow; respawning rigs hollow; eliminated rigs hidden), a warm blink on shielded rigs, a hazard ring around the leader and a fire-coloured ping for 2 s where a rig was wrecked (`wreck_log` entries carry `pos`). `M` toggles it during combat (saved as `[ui] minimap` in `user://profile.cfg`, whose writers keep each other's sections; screenshot mode always shows it); a click on it while spectating watches the rig nearest that spot.
- **Game over awards** (multiplayer): manila tags either side of the standings from `match_stats`: TOP HIVE KILLER, MOST PLAYER KILLS, RAM KING, SCRAP BARON, MOST DEATHS (each only if > 0; ties go to the higher standing) and NEMESIS (the largest `nemesis_n` >= 2: "killer HAUNTED > victim xN").
- VRAM: the rig strips are about 50 MB uncompressed (2560 px wide, 6 to 8 rows of 80 px each); draw cost is about 6 to 14 sprites per rig.

## Entry point and command line

`main.tscn` / `main.gd` parse `OS.get_cmdline_user_args()`:
- *(no args)*: main menu (Solo, Host LAN game, Join LAN game with discovered hosts, driver profile saved in `user://profile.cfg`). The menu hosts with `auto_start = false`, giving a lobby.
- `--solo`: straight into a solo match (the old default)
- `--host`: host a LAN game
- `--join=<ip>`: join a host
- `--shot=<png> --scenario=<name> --seed=<n> --ticks=<n>`: screenshot mode (see `tools/`). Scenarios: `menu`, `join`, `lobby`, `pause`, `skirmish`, `horde`, `workshop` (about 400 ticks), `gameover` (about 300), `gameover_mp` (about 200), `eliminated` (about 220); information UI review: `recap` / `recap_pvp` / `scouting` (about 160, workshop after round 8; scouting with `--hover` on a convoy row), `combat_feed` (about 160), `pvp_grace` (about 90), `spectator` (about 120), `spectator_ws` (about 160), `awards` (about 120), `minimap` (about 150: rigs spread over the arena, a dense pack, a shielded rig and a wreck ping on the radar). The full list is `Scenarios.NAMES`. `--hover=x,y` and `--click=x,y;...` simulate the mouse in screenshot mode, through the same code path as real input.
- `--fast`: short rounds (`fast_rounds`) for quick manual testing.
- Network events are logged as `net: ...` lines on the console.
- Input: mouse; `1`/`2`/`3` pick a card, `R` reroll, `Space` ready, `H` apply the recap's doctrine hint, `T` / `P` the workshop's TECH / RULES view (`Esc` back to PARTS; in combat `P` opens the rule editor as an overlay), `Enter` restart (solo), `Esc` quit. `M` toggles the minimap in combat, `T` the target marks. Spectating: `Tab` / `Right` next rig, `Shift+Tab` / `Left` previous, `Home` / `A` auto camera, click on the minimap to watch the rig nearest that spot. All game actions go through `NetSession.send_command`.

## Dev scripts (`scripts/`)

- `test.sh`: runs the headless test suite and exits non-zero on failure.
- `shot.sh <scenario> <seed> <ticks> <out.png>`: renders a scenario under Xvfb and saves a screenshot: `<out>_1080p.png` is the real 1920x1080 frame (world scaled 3x, UI at full resolution; review this one), `<out.png>` a 640x360 preview filtered down from it.
- `lan-smoke.sh`: starts a headless host and client on localhost through the whole flow (host opens a lobby, the client joins with a colliding name and colour and readies up, the host starts the match, both play) and checks tick sync, command round trip, enemy counts and that names and colours were made unique and agree on both sides; a third client that joins mid-match must get `join_rejected("match in progress")`. LAN discovery (state and player count in the beacon) is checked when UDP broadcast works, else skipped. The harness is `net/smoke.gd` (`--role=host|client|late`).
- `input-test.sh`: drives the real game window under Xvfb with X11 XTEST mouse and keyboard events (menu click, pause and resume, card pick, ready) and fails on unresponsive UI. It runs in CI.
- `playtest.sh`: lets an agent play the game turn by turn and see what a player sees. A session is a seed, a config and the ordered log of the human's commands per decision point (the workshop that opens after round N); each call replays the deterministic sim from tick 0 (about 0.4 s of sim per round, plus about 2 to 6 s of rendering), so no live process is needed. The human is peer 1, opponents are `BotPolicy` bots (`--opponents`, default `balanced,pvp_hunter,random`, 1 to 7 in `ffa`), solo has none; ring spawn positions as `NetSession.spawn_position`, real round timings, `--fast` only for debugging.
  - `playtest.sh new <dir> --seed N --mode solo|ffa [--opponents a,b,c] [--name NAME] [--color 0..7] [--doctrine-drive circle|kite|charge] [--doctrine-target nearest|strongest|players_first] [--fast]` writes `<dir>/session.json` and plays round 1 to the first workshop (`step_01`).
  - `playtest.sh advance <dir> [--commands '<JSON array>'] [--stay] [--no-shots]` records the commands for the current decision point (command dicts as in the round loop contract: `pick_card`, `reroll`, `buy_tech`, `ready`, `set_drive`, `set_target`; applied in order on the tick the workshop opens, before the bots shop), then plays the next combat up to the next workshop or game over. `ready` is optional (the timer ends the workshop anyway). With `--stay` the commands are only recorded (kept in `pending`) and the same decision point is re-rendered, which is how to see the offers after a `reroll`; combat frames are kept, the workshop frame is redone. Invalid JSON or unknown command types exit 2 and record nothing. On a finished game it prints `game over` and the last summary.
  - `playtest.sh status <dir>` prints the latest `summary.txt`.
  - Output per step in `<dir>/step_NN/`: `summary.txt` (token-cheap: round, hp/fuel/scrap/kills, cards, weapons, tech, doctrine, the 3 offers with effects, reroll cost, next tech tier per branch with affordability, orders just applied and what each did, opponents, and a log of the last combat: kills by kind, damage taken by approximate source, hp and alien-count timelines, deaths and respawns, scrap earned and interest, PvP hits, first sightings of new alien kinds, final standings on game over), `state.json` (the same, structured), `frames.json` and screenshots `combat_early|mid|late.png` (ticks where the rig is alive, at 20 / 50 / 85 % of the combat), `workshop.png` or `gameover.png`, each with a `_1080p.png` twin. Timing is printed per call.
  - Parts: `tools/playtest.gd` (headless driver, collector and writer, `--op=new|advance`), `Scenarios.replay_new/replay_advance/replay_done/replay_apply` in `tools/scenarios.gd` (the one replay both processes use, so frames match the summary), and `main.gd` `--scenario=replay --session=<dir> --frames=<frames.json>` (screenshot mode: one process replays once and saves every listed frame). `session.json` stores a hash of `sim/` and the bots; if the code changed between calls the summary carries a WARNING, because older steps then no longer replay identically.
  - Limits: damage attribution is approximate (contact by overlapping enemies, acid and rival shots by hit events near the rig); decals on screen only hold the scars of the current combat; sessions are tied to the sim code version; bots shop instantly when the workshop opens, so opponent stats in the workshop already include their purchases.

## Round loop contract (design doc sections 3, 5 and 8)

Phases (`SimWorld` constants): `PHASE_COMBAT = 0`, `PHASE_WORKSHOP = 1`, `PHASE_GAME_OVER = 2`.
- `world.phase: int`, `world.round: int` (starts at 1), `world.phase_ticks_left: int`, `world.winner_peer: int` (`-1` until game over).
- Durations are tunable constants: `COMBAT_TICKS` (default 70 s; rounds 1–2 shorter, 45 s) and `WORKSHOP_TICKS` (45 s; ready-skip ends it early). `world.fast_rounds: bool` (tests and screenshots) shortens both.
- **Combat:** enemies spawn and scale per round (hp and spawn-rate multipliers; boulders more frequent later).
- **Combat → workshop:** enemies retreat (all removed, with a `"retreat"` event), projectiles are cleared and vehicles stop. Every vehicle earns interest (10% of the scrap held, capped at `interest_cap_for(v)`, see "Economy") and gets 3 fresh card offers.
- **Workshop → combat:** when the timer runs out, or when every alive, non-eliminated player is ready. Then `round += 1`.
- **Fuel reserves:** each vehicle starts with `fuel = 100`. Destroyed: lose 20 fuel (30 if a player killed it, and that player gains 15 scrap as a bounty) and respawn after 3 s (`respawn_ticks`) at full hp, at a free spot. At `fuel <= 0` the vehicle is `eliminated`.
- **Game over:** when at most one player remains in a multiplayer game (`winner_peer` = the survivor), or when the only player is eliminated in solo.

`SimVehicle` additions:
- `fuel: int`, `respawn_ticks: int`, `eliminated: bool`, `ready: bool`, `protect_ticks: int` (third-party protection, see "PvP rules")
- `offers: Array[String]` (3 card ids, empty once picked), `picked: bool`, `reroll_cost: int` (starts at `REROLL_COST_START = 6`, +1 per reroll, resets each workshop)
- `cards: Dictionary` (card id → level 1..3), `tech: Array[String]` (owned tech ids)
- Derived stats recomputed from the base values plus cards plus tech: `max_hp`, `armor` (flat damage reduction), `speed`, `turn_rate`, `scrap_mult`. Weapons are rebuilt from the weapon cards.

Data (`sim/cards.gd`, `sim/tech.gd`, pure data plus apply functions):
- **Cards:** about 16 to start, in 4 categories (`weapon`, `armor`, `mobility`, `behavior`) with a rarity weight. A duplicate pick raises the level (max 3); level 3 cards are no longer offered.
  - Weapons: `mg` (starter), `shotgun` (spread, short range), `cannon` (slow, heavy, pierce 1), `flamer` (very short range, fast ticks).
- **Tech (v2.3):** 72 nodes in `Tech.DEFS` (61 branch nodes in 5 branches of 6 stages plus 11 fusions; ids are indices into the table, so only append). Full node table: `docs/tech-tree.md`. `kind` is `core`, `choice` (exclusive group `<branch>_<tier>`), `proto` (stage 3 prototype, opens nothing) or `fusion_s` / `fusion_l`. Costs: `STAGE_COSTS` = 100 / 140 / 240 / 380 / 520 / 750, `PROTO_COST` 180, `SMALL_FUSION_COST` 200, `LARGE_FUSION_COST` 450. Requirements: `requires` (all) and `any` (at least one non-proto node of the previous stage; stage 4 needs the stage 3 core; `engineering_war_rig` needs `engineering_truck`; fusions need their two parts). Only *active* nodes (owned, requirements active) apply their fx. Helpers: `requirements`, `missing`, `next_step`, `blocked_by`, `active`, `unlocked`, `can_buy`, `price` (dormant fusion = 50%), `buy`, `choices(branch, tier)`, `fusions()`, `fusion_partners`, `ids(branch, kind)`, `branch_tier` (highest owned non-proto stage). Respec: `respec_cost` (first of the match free, then `RESPEC_FEE_PCT` = 50% of the new node), `can_respec`, `respec` (refund old, pay new, fusions without a part go to `v.tech_dormant`, keystones only until bought round + `KEYSTONE_RESPEC_ROUNDS` = 1); command `respec_tech {from, value}`.
  - Effects: the same fx keys as cards plus `pierce` (all weapons), `reroll` (`v.reroll_discount`, scrap off each reroll; also applied at once on purchase), `luck` (`v.card_luck`, offer weight multiplier `1 + luck` for non-common cards), per-weapon `dmg_/rate_/range_<kind>` (added to the global multiplier), `pellets_<kind>` and `splash_<kind>` (flat). `fuel` is a one-off grant paid by `buy()`, not a derived stat.
  - Weapon slots: 2 base, at most 5 (`slots` fx: pickup, auxiliary mount, sidecar, war rig, featherweight).
  - Workshop UI: the TECH view of the workshop (`render/tech_tree_view.gd`, opened with `T` or its tab, drawn into the WorkshopUi canvas through `add_hit` / `is_hover` / `hover_arg`) shows the whole tree over the body; hovering a node marks the nodes still missing on the way to it and sums their cost. The TECH tab's badge counts the nodes you can build now. Screenshot scenario: `tech_tree` (opens the TECH view; `--hover` a node).
- Card offers and rerolls use `world.rng` only, so they stay deterministic.

Commands (validated by `NetSession` allow-lists; ignored in the wrong phase):
- `{"type": "pick_card", "value": int 0..2}`
- `{"type": "reroll"}`
- `{"type": "buy_tech", "value": "<tech id>"}`
- `{"type": "ready"}`
- `set_drive`, `set_target`, `set_rules` and `set_weapon_target` stay valid in every phase.

Snapshots carry all of the above. Card and tech ids are encoded as indices into the data tables.

### Round loop: as built (details and deviations)

Implemented in `sim/sim_world.gd`, `sim/cards.gd`, `sim/tech.gd`, `net/snapshot.gd` (format version 2) and `net/net_session.gd`; tests in `tests/test_rounds.gd`.

- **Timers:** `COMBAT_TICKS_EARLY = 1350` (rounds 1–2, 45 s), `COMBAT_TICKS = 2100` (70 s), `WORKSHOP_TICKS = 1350` (45 s); with `fast_rounds` they are `FAST_COMBAT_TICKS = 120` and `FAST_WORKSHOP_TICKS = 81`. Set `fast_rounds` right after constructing the world (at tick 0 the setter also resets the running timer). A phase flips on the `step()` that brings `phase_ticks_left` to 0. Ready-skip needs at least one non-eliminated player and is evaluated on the next `step()` after the last `ready`.
- **Retreat:** one `"retreat"` event per enemy (`pos`, `owner = -1`, `kind` = enemy kind), thinned by a stride to at most `RETREAT_EVENT_CAP = 150`. `"respawn"` events carry `pos` and `owner` = vehicle id.
- **Repair and respawn timing (additions):** vehicles are repaired to `max_hp` when the next combat round starts. A vehicle that is destroyed when combat ends respawns at once for the workshop, so every non-eliminated player is alive in the workshop. Respawn picks the first free slot of the 8 arena-ellipse slots (starting at the vehicle's own), without using `rng`.
- **Game over:** checked every tick. Multiplayer means `vehicles.size() >= 2`. On game over the field freezes (nothing moves; aliens and projectiles are left as they were). `winner_peer` is the survivor's peer id, `-1` if nobody survives (or in solo). `NetSession` marks a departed peer's vehicle `eliminated`, so a lone host wins when the last client leaves.
- **Scaling (per round r):** hp x `1 + 0.09 (r-1) + 0.005 (r-1)^2` (horde pass: mass instead of sponges), spawn rate x `(1 + 0.35 (r-1))` (`SPAWN_EASE_START = 1.0`: no spawn easing; the in-round wave curve restarts every round, see "Spawn curve"), boulder chance `0.02 + 0.013 (r-1)` capped at 0.2 (balance pass: the horde spawns 2-3x as fast, so the per-spawn share was cut to keep boulders per second near the old level), contact and acid damage x `(1 + 0.06 (r-1)) x early_ease(r, 0.65)`. **Early-round easing** (playtest: the first waves were too strong): `SimWorld.early_ease(r, start)` rises linearly from `start` in round 1 to 1.0 in round `EASE_END_ROUND = 7`, so rounds 7+ are unchanged. `SimWorld.enemy_max_hp(kind, round)` is the hp an enemy spawns with; snapshots encode enemy hp relative to it.
- **Derived stats:** `speed` and `turn_rate` are multipliers (1.0 = base). `armor` is a flat reduction per hit (floor 25% of the hit, also applies to ram damage); per touching enemy per tick it counts `CONTACT_ARMOR_FACTOR = 0.08x`. Extra derived fields: `regen` (hp/s), `contact_damage` (damage per tick to touching enemies, from spikes and berserker; added to `ram_damage`), `ram_mult` (scales the charge ram), `vulture`, `weapon_slots`, `interest_cap`, `reroll_discount`, `card_luck`, `scrap_frac` (scrap_mult remainder). The reroll cost resets to `max(1, REROLL_COST_START - reroll_discount)` each workshop. Scrap from kills is `ENEMY_SCRAP * scrap_mult` with the fraction carried. PvP kill bounty is `PVP_KILL_SCRAP = 15` (x3 for the leader, see "PvP rules").
- **Cards:** `cards` starts as `{"mg": 1}`, so the starter weapon is the level 1 mg card (it can be offered as an upgrade). A weapon card that is not yet owned is not offered when `weapon_slots` are full. Offers are weighted-random without replacement from `Cards.roll_offers(world.rng, v, count, round, exclude)` (draft rules under "Drafts"); maxed cards are never offered. `pick_card` on an index that is out of range, a second pick, or any card command in combat or game over, is ignored.
- **Cards (16):** weapon `mg`, `shotgun`, `cannon`, `flamer`; armor `steel_plates`, `spiked_plating`, `reinforced_hull`, `ablative_scrap`; mobility `v8_engine`, `off_road_tyres`, `nitro`, `caterpillar_tracks`; behavior `scrap_magnet`, `berserker`, `vulture`, `regenerator`.
- **Evolutions (20 cards in all, 4 appended after the 16):** `evo_gatling` (mg + `v8_engine`), `evo_grinder` (shotgun + `spiked_plating`), `evo_earthshaker` (cannon + `caterpillar_tracks`), `evo_inferno` (flamer + `nitro`); category `evolution`, rarity `legendary`, def keys `weapon`, `partner`, `text` (workshop card text naming both ingredients and the result). They are never in the random pool: `Cards.eligible_evolutions(v)` (weapon card at `MAX_LEVEL`, partner owned at any level, evolution card not owned) feeds the end of `Cards.roll_offers`, which puts each eligible evolution into slot 0 (then 1, ...; at least one slot stays free) after the shuffle, so rerolls and bonus offers keep it and no rng is consumed. Picking it grants the card at level 1 (`Cards.grant` refuses a second level; `Salvage.scrap_card` refuses to scrap it); it does not take a weapon slot. `Cards.is_evolved(v, kind)` = evolution card owned and the weapon card still at max level; `_rebuild_weapons` then uses `Cards.EVOLVED[kind]` (scalar stats replacing the level 3 row; tech multipliers, flat pierce / pellets / splash still apply on top) and sets `w["evo"] = true` (always present, false otherwise). **Snapshot:** no wire change: the cards are sent, and `Snapshot._get_vehicle` sets `w["evo"]` from them after decoding the cards. Shots of an evolved weapon carry `Ammo.EVO_BIT` (16) in `proj_ammo` (ignored by `effect_scale`, so render can draw evolved projectiles; clients derive it from `w["evo"]`). Inferno Spout also ignites on every hit (`EVO_BURN_MULT` x hit damage per second, no ammo needed) and every `EVO_FIRE_EVERY` (5) shots drops a `ZONE_FIRE` (`EVO_FIRE_RADIUS` 16, `EVO_FIRE_TICKS` 45) along the stream (3 distances cycling, `_add_zone` merges overlaps). Bot policies score an evolution `BotPolicy.EVOLUTION_SCORE` (100). Tests: `tests/test_evolutions.gd`.
- **Tech costs:** see "Tech (v2.3)" above and `docs/tech-tree.md` (one branch to its keystone 2,130 scrap; all 72 nodes 25,990). `Tech.buy(v, id, round)` pays and recomputes stats.
- **Weapons:** a weapon dict now also has `pellets`, `spread` (half angle), `pierce`, `splash` (radius, applies half damage to other enemies), `speed` (px/s). Projectile ttl = `range / speed + 0.05`, so flames live under half a second. Projectiles gained `proj_pierce: PackedByteArray`, `proj_splash: PackedFloat32Array`, `proj_last: PackedInt32Array` (id of the last pierced enemy); `spawn_projectile(pos, vel, ttl, damage, owner, pierce := 0, splash := 0.0)`. The `"fire"` event `kind` is now the weapon kind index (`Cards.WEAPON_KINDS`: mg 0, shotgun 1, cannon 2, flamer 3) and a volley emits one event. The driving AI orients on `SimVehicle.engage_range()` (mean weapon range).
- **Commands (`NetSession.validate_command`):** `pick_card` accepts an int or an integral float 0..2 (returned as int); `buy_tech` accepts only known tech ids; `reroll` and `ready` ignore any `value`. The 20 commands/s per-peer limit is unchanged.
- **Snapshot:** header gained `phase`, `round`, `phase_ticks_left`, `winner_peer`; vehicles carry fuel, respawn ticks, flag bits, reroll cost, scrap fraction, offers, cards (index + level) and tech (indices), and full weapon dicts. Out-of-range card/tech indices, levels outside 1..3 or an unknown phase make `apply()` return false with the world untouched. Clients recompute derived stats from cards and tech. Event types `retreat` and `respawn` were appended to `Snapshot.EVENT_TYPES`. Projectile pierce/splash are not sent (clients are passive).
- **Checksum** now also covers phase, round, timers, winner, all new vehicle state (fuel, flags, offers, cards, tech, derived stats, full weapon dicts) and the new projectile arrays. It still excludes rng state.
- **Late joiners:** `SimWorld.prepare_vehicle(v)` (called by `add_vehicle` and by `NetSession` when it reuses a slot) sets fuel and, during a workshop, rolls offers.

## PvP rules (as built, design doc sections 7j and 8)

Constants on `SimWorld`: `PVP_START_ROUND = 4`, `LEADER_BOUNTY_MULT = 3`, `LEADER_SCRAP_DIVISOR = 10`, `PVP_PROTECT_TICKS = 60`, `PVP_PROTECT_FACTOR = 0.5`, `RETALIATE_TICKS = 60`.
- **Grace period:** `world.pvp_enabled()` is `round >= PVP_START_ROUND and pvp_grace_ticks <= 0` (render/UI may use it for a "PvP from round 4" hint). Since balance iteration 3 the first `PVP_GRACE_TICKS = 300` (10 s) of round `PVP_START_ROUND` are also safe: `world.pvp_grace_ticks` counts down from 300 when that round's combat begins (not with `fast_rounds`, which skips it) and a `pvp_on` event is emitted on the tick PvP switches on. Before that round `players_first` falls back to alien targeting (vehicles never target players), player projectiles pass through other vehicles, and vehicles that touch only push each other apart (no ram damage). Alien and acid hits are unaffected. The checks sit in `VehicleAI._acquire`, `SimWorld._update_projectiles` and `_resolve_vehicle_contacts`.
- **Bounty on the leader:** `world.leader_peer: int` (-1 = nobody). `update_leader()` runs at the start of every combat tick. Leader score = `kills + scrap / LEADER_SCRAP_DIVISOR` over non-eliminated vehicles; the strictly highest score is the leader, a tie keeps the incumbent if it is among the tied vehicles, else nobody is marked. There is no leader while PvP is off, with fewer than two vehicles in the game, or when the top score is 0. Destroying the leader pays `PVP_KILL_SCRAP x LEADER_BOUNTY_MULT` (45) instead of 15; the fuel loss is unchanged. Render/UI can mark `world.get_vehicle_for_peer(world.leader_peer)`.
- **Third-party protection:** a vehicle that destroys another player's vehicle gets `protect_ticks = PVP_PROTECT_TICKS` (2 s). While > 0 every point of damage it takes (aliens, acid, players, ram, contact) is multiplied by `PVP_PROTECT_FACTOR`. It counts down in combat, is cleared on respawn and at the start of the workshop.
- **Return fire (the "opportunistic" stance, added in balance iteration 2):** when a vehicle is hit by a player that was deliberately targeting it (`attacker.target_kind == 2` and `attacker.target_id == victim.id`, or one of the attacker's weapons has its own target on the victim; `SimWorld._aims_at`, so stray shots at aliens do not count), it remembers the attacker for `RETALIATE_TICKS` (2 s; `SimVehicle.retaliate_id` / `retaliate_ticks`, AI scratch: host-only, not in the checksum or snapshot, cleared on respawn and in the workshop). While the memory lasts, `VehicleAI._acquire` targets that attacker (any doctrine except `players_first`, which already hunts players) if it is alive and in weapon range, else falls back to the normal choice. Without it, a `players_first` rig farmed rivals that never shot back (74-83% ffa win rate in the first league).
- `leader_peer` and `protect_ticks` are in the checksum and in the snapshot (version 4); tests in `tests/test_pvp.gd`.
- **Iteration 3 additions** (all tested in `tests/test_iteration3.gd`):
  - **Invulnerability / newbie protection:** `SimVehicle.invuln_ticks` (`INVULN_TICKS = 90`, 3 s) is set on respawn and when a combat from round 2 on begins, cleared in the workshop. While > 0 the vehicle takes no damage from anything, enemy and player projectiles pass through it, and `VehicleAI` never targets it (a `players_first` rig switches target; return fire ignores it). Render should show a shield or blink. Not applied to round 1 (nothing threatens a rig in its first seconds).
  - **`players_first` target choice:** the marked leader if in weapon range, else the in-range rig with the highest `leader_score` (nearest among equals). Never "the weakest", so a hunter does not farm newcomers.
  - **Underdog:** `world.is_underdog(v)` is true for the non-eliminated rig with strictly the lowest fuel (needs a second rig). Its fuel loss per death is x `UNDERDOG_FUEL_FACTOR = 0.7` (alien 20 -> 14, player 30 -> 21).
  - **Fuel economy:** a player kill moves `min(FUEL_STEAL = 10, victim's loss)` fuel to the killer (cap `START_FUEL = 100`; plus `LEADER_FUEL_BONUS = 10` for the marked leader). Reward share for killing the same victim again in one round: 100% / 50% / 0% (`REPEAT_KILL_FACTORS`, applied to the scrap bounty and the fuel; resets every combat; the kill still counts). **Drain:** at the start of every workshop after round `FUEL_DRAIN_START_ROUND = 7` (`PVP_START_ROUND + 3`) in a game with 2+ rigs every non-eliminated rig loses `fuel_drain_for_round(round)` = 6 + (round - 7) / 3 fuel (7..9: 6, 10..12: 7, ...), never below 1 until round `FUEL_DRAIN_LETHAL_ROUND = 18`; from the workshop after that round the drain can take the last point and eliminate every rig except the one with the most fuel (first on ties), so a stalled match is decided by round ~19. Only kills (steal) offset the drain. `world.fuel_drain` holds the current amount (0 before round 7 and in solo, where nobody can take fuel and the hive curve already ends the run); a `drain` event per rig (`owner` = vehicle id, `kind` = fuel lost).
  - **Contact damage reduction:** derived stats `contact_reduction` (fraction of enemy contact damage ignored: spiked plating 10% per level, berserker 12% per level, capped at `MAX_CONTACT_REDUCTION = 0.6`) and `thorns` (spiked plating, 0.5 per level: the touching enemy takes that fraction of the contact damage it would deal, per tick, on top of the spikes' `contact_damage`). The `charge` drive does not target boulders (nor ram them) unless the `berserker` card is owned; with only boulders in reach it shoots from a circle.

## Doctrine rules (as built, design doc section 6)

Programmable behaviour lives in `sim/doctrine.gd` (`class_name Doctrine`, pure data, parsing and evaluation) and is run by the sim every combat tick; tests in `tests/test_doctrine.gd`.
- **Rule:** `{"if": [[cond_id, op, value], ...], "do": action}`. Up to `MAX_CONDS = 3` conditions, all must hold (none = always). Conditions (`Doctrine.CONDS`): numeric `hp` (own hp %), `swarm` (aliens within `SWARM_RADIUS = 220`), `rivals` (rival rigs within `RIVAL_RADIUS = 380`, 0 while PvP is off), `t_dist` (px to the target), `t_hp` (target hp %) with `<` / `>` and an int in the listed range; flags `t_player`, `t_boulder`, `t_spitter`, `pvp`, `has_target` with `=` 0 / 1. A target condition without a target is false.
- **Actions:** rig lists take `drive:circle|kite|charge|flee|hold` and `target:nearest|strongest|weakest|players_first|boulders|spitters`; weapon lists take `target:` (the same plus `follow`) and `fire:hold|free`. Rules are read top to bottom and the first match **per action group** wins (rig: drive, target; weapon: target, fire). What no rule sets falls back to the base: the rig's `doctrine`, the weapon's `weapon_doctrine[kind].target` (default `follow`).
- **Slots:** `Doctrine.slots(v) = BASE_SLOTS (2) + the summed `rule_slots` fx (rangefinder, targeting computer, neural fire control)`, at most `MAX_SLOTS = 6`, per list. Lists may hold up to `MAX_SLOTS` rules; the ones beyond the vehicle's slots are stored but not run (the editor shows them as locked). Weapon doctrine is keyed by weapon kind and survives `Cards.recompute()`.
- **Evaluation:** `SimWorld._update_vehicles` calls `Doctrine.apply_rig()` before `VehicleAI.update_target()`: it sets the scratch `eff_drive` / `eff_target` (what steering and targeting use) and `rule_live` (bit i = rule i matched). A changed `eff_target` re-targets at once (`acquired_mode`). `_fire_weapons` calls `Doctrine.apply_weapon()` per weapon (target conditions look at the weapon's own target, else the rig's; the match mask goes to the weapon's `live` key) and `VehicleAI.update_weapon_target()`: `follow` uses the rig's target; any other mode keeps its own target in the weapon dict (`tk`, `ti`, `tid`, `tp`, `tv`, `tmode`), picked by `VehicleAI.find_target()` within that weapon's range every `RETARGET_TICKS`, falling back to the rig's target when nothing matches. `fire:hold` still aims, but does not shoot. After the fallback, every weapon records what it is on this tick in `ak` (0 none, 1 alien, 2 rig, like `target_kind`), `aid` (enemy or vehicle id) and `ap` (position); AI scratch, not in the checksum, but sent in the snapshot (version 15) for the target marks. `flee` drives away from the target at `SPEED_FLEE`; `hold` stands and faces it.
- **Text form** (commands, tests, tools): rules joined by `;`, each `cond&cond|action`, e.g. `hp<30|drive:flee;swarm>20&t_dist<120|drive:charge`. `NetSession.validate_command` parses `set_rules` and re-encodes it canonically (max `MAX_TEXT = 400` chars); `set_weapon_target` needs a weapon kind and a `WEAPON_TARGETS` mode.
- **Checksum and snapshot:** `Doctrine.fingerprint(v)` is hashed into `checksum()`. Snapshot v7 sends per vehicle a `live` byte per weapon, `rule_live`, the rig rules and the weapon doctrines (kind string, target index, rules) in a binary form indexed by `Doctrine.COND_IDS`, `OPS` and `ACTIONS` (append-only tables); unknown entries are dropped on receipt.
- **UI:** `render/doctrine_editor.gd` (`DoctrineEditor`, `WorldView.rules`, an amber CRT). In combat `P` toggles it as a full-screen overlay on the HUD layer. In the workshop it is the RULES view: `WorkshopUi` embeds it into its body with `open_embedded(rect)` (mouse filter ignore; the workshop forwards clicks below its top bar through `click_at`), `P` / `Esc` switch the workshop view, and an editor left open from combat moves into the RULES view when camp starts. Tabs for the rig and each mounted gun, base settings, the rule rows (dropdowns for conditions and actions, `<`/`>` or YES/NO, `-`/`+`, UP/DN, X, a plain-language sentence per rule, a lamp lit while the rule matches in combat), quick-add templates and hover help. The open list is a local working copy; every edit sends the whole list as one `set_rules`. Screenshot scenarios `rules` and `rules_weapon` (combat overlay); the workshop's RULES view is `workshop` with `--click=410,16`.

## Spawn curve, drafts and economy (balance iteration 3)

- **Spawn curve (horde pass):** `spawn_rate_at(round, ticks_into_combat)` = `SPAWN_RATE_START (3.0) x wave_mult(t, dur) x spawn_rate_mult(round)` enemies per second. `wave_mult`: build-up 0.8 -> 1.0 until 35 % of the round, first surge x2.2 until 50 %, a `WAVE_LULL_TICKS = 180` (6 s) lull at x0.3, then the final surge 2.0 -> 2.8 until the round ends (the end-of-round retreat follows). `surge_starts(dur)` gives the two surge start ticks. **"surge" event:** `SURGE_WARN_TICKS = 60` ticks before each surge `_emit("surge", centre of the alive vehicles, -1, index, {"in_ticks": 60, "index": 0 or 1})` (snapshot extras `in_ticks`, `index`; Snapshot VERSION 12). Surges whose warning tick would be negative (fast rounds) are skipped. **Packs:** the accumulator counts spawn events; a mite event spawns `pack_size(r)` mites (`3 + 0.6 (r-1)`, max 8) within `PACK_RADIUS = 24` px of one edge point (clamped to the spawn area); boulder and spitter chances are per event and multiplied by the pack size (boulder <= 0.5, spitter <= 0.3 per event) so packs do not dilute them. **Alive caps:** `boulder_cap(r)` = `min(8 + 3r, 48)`, `spitter_cap(r)` = `min(3 + r / 2, 12)`; a spawn that would exceed a cap becomes a mite. **Spitter spreading:** at most one spitter spawn per `SPITTER_SPAWN_GAP = 75` ticks, never from the same spawn-area edge twice in a row. **Mites:** hp 4, speed 78 px/s (was 90: with 90 a kiting rig, speed 96 + cards, was caught by packs), contact damage 0.15 per tick, scrap per kill `mite_scrap(r)` = `0.19 + 0.009 (r-1)` (min 0.06) (fractional, carried in `scrap_frac`) so the bigger horde keeps the old scrap income.
- **Drafts** (`Cards.roll_offers(rng, v, count = 3, round_no = 0, exclude = [])`): never `count` cards of one category; while a weapon slot is free and a weapon the vehicle does not own is offerable, one offer is a new weapon; in rounds 1..`Cards.EARLY_ROUNDS = 3` unowned weapons weigh double; cards in `exclude` (the previous offer: `reroll` passes it) are not offered again unless fewer than `count` others exist; the final order is shuffled with the world rng. Filler commons were thinned (steel plates 8, V8 engine 6, off-road tyres 5, scrap magnet 6, reinforced hull 6). Defence was buffed to match the steeper hive: steel plates +60 hp / +1.5 armour per level, reinforced hull +110 hp, ablative scrap +3 armour, regenerator 2.5 hp/s.
- **Economy:** interest at the end of a combat is `world.interest_for(v)` = `min(scrap / 10, world.interest_cap_for(v))` (10% of held scrap) with `interest_cap_for(v)` = `v.interest_cap + INTEREST_CAP_PER_ROUND (2) x round`, where `v.interest_cap` is still 5 plus the salvage tech bonus (+2, +3). UI must use these two functions rather than `v.interest_cap` alone.

## Spitters (as built)

Constants on `SimWorld`: `SPITTER_MIN_ROUND = 3`, spawn chance `spitter_chance(r)` = 0 before round 3, then `0.08 + 0.03 (r-3)` capped at 0.25 (rolled after the boulder roll; no extra rng draw before round 3, so rounds 1-2 are unchanged). A spitter (hp 20, speed 55 px/s) holds 180 to 230 px from the nearest living vehicle (`SPITTER_KEEP_MIN/MAX`: backs away with a sideways drift when closer, closes in when farther, strafes slowly in between) and every `SPIT_PERIOD = 60` ticks (2 s, staggered by enemy id, so there is no extra per-enemy state) lobs one acid glob if the target is within `SPIT_RANGE = 260`: speed `SPIT_SPEED = 170` px/s, damage `SPIT_DAMAGE = 8` x `enemy_damage_mult(round)`, aimed with target lead and +-0.08 rad error (from `world.rng`), ttl about 1.8 s. The projectile has `owner = -1`; it damages vehicles only (armour applies, the kill costs fuel as an alien kill) and passes aliens by. Each shot emits `{"type": "spit", "pos": muzzle, "owner": -1, "kind": SPITTER}` for render. The old screenshot scenarios that fake spitter fire in `tools/scenarios.gd` now double up with the real thing and can drop their fake.

## Bosses (as built, design doc sections 7f and 7j)

`sim/bosses.gd` (`class_name Bosses`, static, pure) plus the `boss_*` fields and small hooks in `SimWorld`; tests in `tests/test_bosses.gd`. Bosses are ordinary entries of the enemy arrays (kinds `BOSS_A / BOSS_B / BOSS_SHARD`, radius 36 / 34 / 22; `ENEMY_RADIUS / SPEED / HP / CONTACT_DAMAGE / SCRAP` have nine entries (kinds 0..8), `MAX_ENEMY_RADIUS = 36`), so targeting, shots, splash, burn and ramming work unchanged. Their hp is NOT `ENEMY_HP`: use `world.enemy_max_hp_of(j)` (the static `enemy_max_hp(kind, round)` is for kinds 0..5 only).
- **Schedule (pure, known at match start):** `Bosses.is_boss_round(r)` = r >= 4 and r % 4 == 0; `first_for_seed(seed)` (stored as `world.boss_first`, 0 = Tripod first) decides the opener and the two bosses alternate (`kind_for_round(first, r)`); `enraged_in(r)` = r >= 12. `Bosses.next_boss(world) -> {"round", "kind", "enraged", "name"}` is the workshop's "next boss in round 4: TRIPOD QUEEN" (in a workshop the round about to start counts, in combat only later rounds). `Bosses.boss_name(kind)`.
- **Round state** (reset lazily by `Bosses.tick` when `world.round != world.boss_round`; also on clients through the snapshot): `boss_kind` (-1 = no boss this round), `boss_state` (`Bosses.ST_NONE | WARNED | ACTIVE | KILLED | RETREATED`), `boss_phase` (0 before the spawn, 1..3), `boss_enraged`, `boss_max_hp` (the shared pool, `Bosses.max_hp_for(round, alive vehicles)` = `HP_BASE 450 x kind mult (Tripod 0.8, Colossus 1.1) x (1 + 0.1 per round after 4) x (1 + 0.8 per extra alive vehicle)`), `boss_hp_frac` (hp of all boss bodies / max, 0..1), `boss_warn_left` (ticks to the spawn while WARNED), `boss_spawn_pos`, `boss_marks`. Host only: `boss_ents` (enemy id -> attack state), `boss_dealt` (vehicle id -> damage), `boss_dmg_taken`, `boss_ticks`, `boss_log` (rows for the bot league), `boss_forced` (tests / scenarios: boss even with `spawning_enabled = false`; otherwise `spawning_enabled` gates bosses too).
- **Flow** (`Bosses.tick(world)` runs first in `_step_combat`): at `surge_starts(dur)[0] - 90` ticks a `boss` event (the spawn point, `in_ticks`, `enraged`), at the first surge the `boss_spawn` event and the body spawns on the arena edge nearest the alive rigs' centroid (`Bosses._spawn_point`). While WARNED / ACTIVE regular spawns run at `BOSS_SPAWN_FACTOR = 0.5`. Phases follow the main body's hp (66% / 33%), each change emits `boss_phase` (kind = the new phase). The round timer ending with the boss alive emits `boss_retreat` (no penalty; `_begin_workshop` calls `Bosses.end_round`).
- **Tripod Queen:** artillery. Every `VOLLEY_TICKS` (160; 110 in phase 3, shells 1 / 3) she marks the predicted position of the nearest rig(s) with a `MARK_SHELL` marker (radius 56, 36 ticks = 1.2 s) and emits `boss_shell`; the shell detonates when `left` reaches 0 (`boss_blast`, kind = radius; `SHELL_DAMAGE 26 x enemy_damage_mult` to rigs inside, through armour, `SRC_BOSS`). Phase 2+: a mite brood from her body every 130 ticks (`boss_brood`). She holds 90..150 px from the nearest rig (tuned down from 170..290 so ordinary guns reach her; hp multiplier `TRIPOD_HP_MULT` 0.38; `COLOSSUS_HP_MULT` 1.0) (fast entry from the edge), phase 3 walks 1.4x faster.
- **Shard Colossus:** `MARK_RING` glow on the body for 30 ticks, then a ring of 14 (18 in phase 2) slow alien projectiles (`proj_owner = -1`, speed 95, 4.5 s, 9 x damage mult; `boss_ring`). Phase 2: charges (`MARK_CHARGE` lane for 30 ticks from the body to the locked end point, then 22 ticks at 380 px/s; impact 30 x damage mult once; `boss_charge`). At 33% the body vanishes and `SPLIT_COUNT = 3` `BOSS_SHARD` minibosses (hp = max/6 each, a smaller ring each) spawn (`boss_split`); the body cannot be killed before the split (`_hit_enemy` clamps to 1 hp). The boss is killed when every body is dead.
- **Enrage** (round >= 12): speed x1.25, attack cooldowns x0.7 (`Bosses.speed_of`, `_cd`).
- **Contact, ram, EMP:** boss contact damage goes through `_boss_contact` (`SRC_BOSS`, counted as "acid" in `round_stats["taken"]`); a ram does `RAM_DAMAGE_FACTOR = 0.3` of its damage to a boss and costs the rammer `RAM_RECOIL` extra per contact tick, no ram knockback; `stun_enemy` on a boss only applies the oil-style slow (`EMP_SLOW_MAX = 45` ticks).
- **Reward:** `Bosses.on_death` (called from `_hit_enemy` when the last body dies): every vehicle with >= 10% of the boss hp dealt gets `25 + 6 x round` scrap (x2 for the killing blow, x `scrap_mult`), `round_stats["boss_bounty"]`, event `boss_kill` (owner = killer id, kind = boss kind); the killer gets `bonus_offers += 1` and `boss_rare = true`, so its next draft has 4 offers with one rare-or-better card (`Cards.roll_offers(..., min_rare)`).
- **Targeting:** `strongest` already picks a boss; new rig / weapon target `boss` (`Doctrine.RIG_TARGETS / WEAPON_TARGETS`, action `target:boss`, nearest boss body in range, else nearest alien) and condition `boss_active` (flag: `boss_state == ACTIVE`). Appended to the binary index tables.

The 3-bit enemy kind sends 6 for every boss kind; the block restores the real kind and hp. Clients never run the attacks; they render `boss_marks` and the bodies.
- **Boss visuals** (`render/boss_view.gd`, `BossView`, child of `WorldView`; it only reads the world and the events).   - **Bodies:** the Tripod faces the nearest rig; `aim` in the last 24 ticks before a volley (exact from `boss_ents` on the host, predicted from the last `boss_shell` + `Bosses._cd` on clients), `fire` for 9 ticks after a shell, else walk. The Colossus shows `windup0/1` from its position-matched marker (markers carry no enemy id), `windup1` while charging (speed > 250), `hurt` after a phase change. Hit flash from `WorldView` hit cells; a glow pulse in phase 3 / enraged.
  - **Telegraphs** (normal alpha, a 4x4 Bayer dither for fills): `MARK_SHELL` = the telegraph sheet by progress plus a countdown sweep, closing brackets and a blink in the last 6 ticks, the shell arcing from the sac (2x at the top, ground shadow); `MARK_CHARGE` = a dithered cyan lane that fills in, with running chevrons and an end bar; `MARK_RING` = a swelling dotted ring and the body glow.

## Species and the hive signature (as built, design doc 7a and 7c)

`sim/species.gd` (`class_name Species`, static, pure) plus small hooks in `SimWorld`; tests in `tests/test_species.gd`.
- **Kinds:** `GLASS = 3`, `BROOD = 4`, `SHRIEKER = 5`, with damage sources `SRC_GLASS = 7`, `SRC_BROOD = 8`, `SRC_SHRIEKER = 9`. Boss kinds were renumbered to 6..8 (all code uses the constants).
- **Signature:** `Species.signature(seed) -> PackedInt32Array` (index 0 glass, 1 brood, 2 shrieker; value 0 = inactive, otherwise the first round, 3..7; exactly two active). It uses its own RNG, so `world.rng` is untouched. `SimWorld.hive_first` holds it (part of the checksum). `Species.roll(w, counts)` is called from `_spawn_tick` on mite events and only draws from `world.rng` when a species is active and below its cap.
- **Glass wings** run a pure function of (tick, id): period 150 ticks, dive 100..132, flocks of 4 ids share a phase, so clients derive pose and dive state without extra data. In `_update_enemies` they only touch rigs while diving; ram, thorns, ground zones, the flamer weapon (`EVO_FLAMER_IDX`) and splash skip them.
- **Brood carriers:** `_hit_enemy` calls `Species.on_brood_death`; the mites are queued in host-only `brood_pending` and released after `BROOD_DELAY = 6` ticks, unless the kill was fire/burn/splash (`_fire_dmg`, `_in_splash`, `enemy_burn_ticks`, FIRE ammo, flamer). Event `brood` (kind 1 hatched, 0 died with the carrier).

War machine: a ram hit with at least 40 momentum sends a 60 px, 30 damage shockwave with knockback around the rig (costs 40 momentum; per-target throttle 30 ticks in `v.ram_fx[1000 + id]`, event `shockwave`; rivals too in PvP). Spotter: a cannon shot at a spitter is spawned on it (cannot miss) and deals +50 %.

- **Snapshot v11:** vehicle extras flag 64 carries the salvage group (contract offers, contract kind / need / reward / progress, loan debt and instalments left, reserved card, bonus offers), so rigs without it pay nothing.
